Help Center

Current app behavior, verification rules, and feed mechanics.

What Is KarmaRace?

KarmaRace is a task exchange app where users publish verifiable tasks and other users complete them to earn karma. Feed visibility is influenced by owner karma, while task checks determine reward transfers.

How It Works

  1. Create a task in My Tasks (new tasks start hidden).
  2. Publish explicitly — publish runs configuration checks and can fail with a reason.
  3. A tester opens the feed and gets one card at a time.
  4. Check queues async verification and shows loading until completion state updates.
  5. On CONFIRMED, tester earns karma and owner pays karma.

Background Worker Requirement

Async checks and notification deliveries require a Procrastinate worker process. In local development, run a worker alongside runserver: 

python manage.py procrastinate worker

If worker capacity is temporarily unavailable, jobs remain queued in the database and are processed when workers resume.

Feed Selection and Filters

Feed is ranked by owner karma (descending), then creation time. Owners never see their own tasks in feed. Tasks do not auto-expire from feed by age.

  • Completion filter: Not Completed / Completed
  • Archive filter: Not Archived / Archived
  • Task Type filter: Webhook / Not Webhook

Health Checks and Visibility

Feed selection runs task health checks. Visibility uses a two-strike policy:

  • First consecutive health failure: task is marked suspect but remains visible.
  • Second consecutive health failure: task is hidden and owner receives a health-failed notification.
  • A later successful health check resets failure streak and can auto-unhide a task hidden by health checks.

Reciprocity Obligations

Reciprocity is always on. If you have open obligations and matching cards are currently available, your feed is restricted to tasks that can satisfy those obligations, and archive/skip is disabled. If no matching obligation card is available, feed falls back to normal cards. Cards shown in this mode are tagged as Obligation.

On successful checks for GitHub task types:

  • If a matching open obligation exists, it is settled and removed.
  • Otherwise, a reverse obligation is created.

Webhook tasks are excluded from obligation creation and settlement.

Task Types and Verification

  • GitHub Star: target format owner/repo, verified against tester linked GitHub account.
  • GitHub Fork: target format owner/repo, verified against tester linked GitHub account.
  • Webhook: target format full URL, publish is Pro-only, verified by endpoint JSON response.

Webhook Contract

When a webhook task is checked (and during publish health checks), KarmaRace sends:

POST {task.target_id}
Content-Type: application/json
Authorization: Bearer {task.webhook_secret}  # only if secret is set

{
  "task_slug": "webhook-vic-https-example-com-verify",
  "platform_username": "tester_username"
}

Expected response:

{ "verified": true }

If verification fails, KarmaRace reports Sent/Expected/Got diagnostics to help debugging. Webhook cards show a failure signal: tried_failed / (completed + tried_failed + not_tried + epsilon).

Reward and Threshold Config

Fixed reward values per task type and low-balance threshold are defined in setup/platform_rules.py, with optional per-user overrides through UserPreference.

Linked Accounts

Connect GitHub and Discord from Linked Accounts. OAuth tokens are used for verification requests. If checks fail due to missing token, disconnect and reconnect the provider.

Clicking Discord from the footer opens the server flow: if you are logged out you are sent to app login, if your Discord link is valid you are sent directly to the guild, and if your link is stale (left server) the old mapping is removed and relink is required.

On successful Discord link, KarmaRace joins your Discord account to the configured guild, assigns the configured role, and syncs your guild nickname to your app username. When you later change your app username, KarmaRace attempts to sync Discord nickname again.

Common Publish Failures

  • Webhook tasks are Pro-only.
  • GitHub repo is private or missing.
  • Webhook endpoint is unreachable or does not return JSON with a boolean verified field.

Check Result Messages

Checks now return precise result text. Typical failure messages include:

  • GitHub star/fork not detected yet for your linked account.
  • Webhook returned unexpected JSON or unreachable endpoint errors.
  • Verification timed out.
  • Task was archived/unpublished before verification completed.

Notification Payloads By Event

In-app notifications store event-specific payload JSON. Current payload shapes:

  • TASK_CONFIRMED: {"task_id": number, "delta": number} (delta optional depending on producer)
  • TASK_HEALTH_FAILED: {"task_id": number, "task_type": string, "target_id": string, "owner_id": number}
  • KARMA_LOW: {"delta": number, "balance": number, "threshold": number} (fields may vary by producer)
  • KARMA_RESTORED: {"delta": number, "balance": number, "threshold": number} (fields may vary by producer)
  • APPRECIATION: {"message": string}
  • PROJECT_STATE: app-defined JSON object for project state updates
  • FLAG_UP_RECEIVED: app-defined JSON object for received flag-up events
  • FLAG_UP_SENT: app-defined JSON object for sent flag-up events
